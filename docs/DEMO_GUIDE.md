# MindTrace Demo Guide

This guide is for a local portfolio, hackathon, or submission demo. Use only fictional data. Do not use real journal content, real users, or real Gemini credentials during the standard demo.

For the final run-of-show checklist, see `docs/FINAL_DEMO_CHECKLIST.md`. For concise submission copy, see `docs/SUBMISSION_SUMMARY.md`.

## Demo Setup

Prerequisites:

- Node.js 24
- pnpm 11.8.0
- Java 21
- Google Chrome or Playwright Chromium

Install dependencies:

```powershell
pnpm install --frozen-lockfile
```

Run the local app and emulators:

```powershell
pnpm test:e2e
```

For an interactive manual demo, run Firebase Emulator and Next.js separately:

```powershell
pnpm emulators:start
pnpm dev
```

Then open:

```text
http://localhost:3000/zh-CN
```

## Recommended Demo Flow

1. **Open the app**
   - Start from `/zh-CN`.
   - Explain that unauthenticated users are redirected to login.

2. **Register or log in**
   - Use a fictional `example.test` email.
   - Explain that Firebase Authentication handles email/password auth.

3. **Complete basic consent**
   - Confirm adult status.
   - Accept product boundary and privacy notices.
   - Set an IANA time zone such as `Asia/Tokyo`.
   - Explain that AI consent is separate and optional.

4. **Show the MVP overview**
   - Visit `/zh-CN`.
   - Walk through the cards: record today, history, trends, long-term summary, plans, AI reflection boundaries.

5. **Create a journal entry**
   - Go to `/zh-CN/today`.
   - Enter fictional values, for example mood 6, stress 5, energy 4, sleep 6.5 hours, sleep quality 5.
   - Select controlled tags such as study and sleep.
   - Use fictional note text only, for example: “今天完成了学习任务，下午有点累，晚上准备早点休息。”

6. **View today/history**
   - After save, open the record or go to `/zh-CN/history`.
   - Explain that history uses API pagination and does not render full long notes in the list.

7. **Open entry detail**
   - Show full record detail.
   - Point out edit/delete controls and revision behavior if needed.

8. **View trends**
   - Go to `/zh-CN/trends`.
   - Explain that the page uses the latest seven user-local dates.
   - Mention that multiple records on the same local date are averaged and missing dates stay empty rather than becoming 0.

9. **View long-term summary**
   - Go to `/zh-CN/long-term`.
   - Switch 7/14/30 day windows.
   - Explain that deterministic summaries do not call Gemini and do not copy full journal text.
   - If data is insufficient, use that state to explain the “record a few days first” flow.

10. **Create a manual plan**
    - Go to `/zh-CN/plans`.
    - Create a fictional manual plan and add an action item.
    - Mark the action item complete.

11. **Show AI feedback entry point**
    - Open an entry detail page.
    - Click “生成 AI 反馈”.
    - If AI consent has not been accepted, show the independent AI data processing dialog.
    - Explain that declining AI consent does not block journal, history, trends, summary, or manual plans.

12. **Show AI plan suggestion draft entry point**
    - Go to `/zh-CN/plans`.
    - Show the AI plan suggestion area.
    - Explain that AI can only generate a draft; it is not saved as a plan until the user confirms.

13. **Show AI long-term insight draft entry point**
    - Go to `/zh-CN/long-term`.
    - Show the AI long-term insight area.
    - Explain that it uses aggregate summary fields, not full journal history.

14. **Explain safety and privacy**
    - Open product boundary and safety pages.
    - State clearly: MindTrace is not a diagnosis, treatment, medication, or emergency-response product.
    - Crisis/supportive redirect copy is fixed locale text, not generated by the model.

## Fake Provider Versus Real Gemini

Default demo and tests:

- Use Firebase Emulator, fake users, Fake Provider, SDK mocks, and route mocks.
- Do not call real Gemini.
- Do not require `GEMINI_API_KEY` or `GEMINI_MODEL`.

Real Gemini validation:

- Is manual only.
- Requires server-side `GEMINI_API_KEY` and `GEMINI_MODEL`.
- Uses `pnpm smoke:gemini`.
- Must not print API keys, full prompts, raw model output, user IDs, emails, cookies, tokens, Firestore paths, or real journal content.

## Suggested Talking Points

- “This is a private journaling and self-reflection MVP, not a clinical product.”
- “The most important engineering boundary is that all user data access is server-session scoped.”
- “AI is optional and separated from the core journal product.”
- “The app fails closed: unsafe or malformed AI output is discarded and replaced with a safe fallback.”
- “The demo uses fictional data and emulators; no real Firebase project or real Gemini request is required.”

## Demo Checklist

- Use fictional email and journal content.
- Confirm no `.env.local` or real keys are present.
- Do not run real Gemini unless explicitly doing a separate smoke test.
- Do not describe AI output as diagnosis, therapy, or professional advice.
- Do not claim the app is deployed or commercially launched.
