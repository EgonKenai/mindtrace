# MindTrace 实施计划

## 1. 计划约束

- 本计划最多六个开发阶段。
- 每个阶段完成后运行格式检查、严格类型检查、单元测试和该阶段相关的集成/E2E 测试。
- 未通过验收标准不得把阶段标记完成。
- 首版采用模块化单体，不增加社区、私聊、公开动态或咨询师市场。
- 规划阶段不安装依赖、不生成业务代码。
- 具体依赖版本在阶段 1 查询官方维护状态后锁定。

## 2. 阶段 1：工程基础、身份和同意

### 目标

建立可在 Windows 本地运行的 Next.js 严格 TypeScript 工程、环境配置、Firebase Emulator、简体中文国际化骨架、身份会话和首次同意流程。

### 工作范围

- Next.js、TypeScript strict、格式化、lint 和测试工具
- Firebase Auth 邮箱注册、登录、退出
- ID token 换取安全会话 Cookie；会话创建不依赖成年确认或同意状态
- `accounts` 和版本化 `consents`
- `[locale]` 路由与 `zh-CN` 消息目录
- 公共产品边界页和安全资源页骨架
- `.env.example`、`.gitignore` 和 Windows README
- CI 基础检查

### 验收标准

- Windows 按 README 可启动 Web、Auth Emulator 和 Firestore Emulator。
- `npm run format:check`、`npm run lint`、`npm run typecheck`、`npm test` 均通过。
- TypeScript 开启 strict，生产代码没有未说明的 `any`。
- 用户可注册、登录、退出；服务端验证有效 ID token 后即可创建会话，无效和过期 token 被拒绝。
- 会话创建接口不读取或要求成年确认、同意记录，因此新用户不会被阻止进入 onboarding。
- 已登录但未完成成年确认或当前版本同意的用户可访问 onboarding、设置、产品边界和安全页面。
- 未完成成年确认或当前版本同意的用户不能访问日记、趋势、AI 反馈和报告等个人页面或 API。
- 成年确认和同意记录包含各文案版本、语言和服务端时间。
- 未登录用户可访问产品边界和安全资源页。
- 仓库不包含真实密钥、服务账号 JSON 或真实日记。

## 3. 阶段 2：日记、历史和 7 天趋势

### 目标

完成不依赖 AI 的核心记录体验。

### 工作范围

- 每日记录表单和服务端 schema
- 日记创建、读取、编辑、删除
- 历史列表、详情和基础筛选/分页
- 最近 7 天趋势聚合和图表
- 用户时区与本地日期处理
- 受控生活事件标签

### 验收标准

- 合法记录可创建；越界数值、非法标签、超长文本和错误日期均由服务端拒绝。
- 同一天可创建多条记录，7 天趋势按用户时区稳定聚合。
- 历史默认按发生时间倒序，并支持打开单条详情。
- 编辑递增 `revision`；删除清理该记录已有的关联占位数据。
- 用户 A 不能通过猜测 ID 读取、编辑或删除用户 B 的记录。
- Firestore 客户端直接读写业务集合被安全规则拒绝。
- 桌面和移动视口下表单、历史和趋势无文本溢出或控件重叠。
- 单元、Emulator 集成和关键 E2E 测试通过。

### 阶段 2A：日记数据模型、服务端验证和 API

阶段 2A 只实现后端数据模型、服务端 schema、Firestore repository、service 和 `/api/v1/entries` API；不实现页面、趋势图、Gemini、AI 反馈、支付、报告、导出或账户删除。

已采用的实现细节：

- 日记正文和结构化字段保存在 `journals/{uid}/entries/{entryId}`，`uid` 始终来自服务端会话验证，不接受客户端 owner 字段。
- 生活事件标签首版为受控 ID，最多 5 个且不允许重复；中文展示名位于 `src/i18n/messages/zh-CN.ts`。
- `GET /api/v1/entries` 使用稳定游标分页，默认按 `occurredAt desc` 排序，游标包含 `occurredAt`、`createdAt` 和 `entryId`。
- `POST`、`PATCH`、`DELETE` 执行同源 Origin/CSRF 防护；所有响应使用字段白名单。
- 不存在和不属于当前用户的 `entryId` 都返回同一 `NOT_FOUND` 错误，不泄露其他用户资源是否存在。
- 当前阶段新增集合 `journals/{uid}/entries` 已加入未来导出和账户删除覆盖要求；本阶段不实现导出和账户删除。

### 阶段 2B：记录、历史、详情编辑和删除页面

阶段 2B 实现 `/[locale]/today`、`/[locale]/history` 和 `/[locale]/entries/[entryId]`，复用阶段 2A 的 schema、字段定义和 API。

已采用的实现细节：

- 创建和编辑共用 `JournalEntryForm` 及字段组件；客户端校验使用共享 Zod schema，服务端仍是最终权威。
- 历史页面按 `occurredAt` 倒序加载，每页 10 条并使用 `nextCursor` 追加，不做全量读取。
- 详情页面使用统一的安全错误处理；不存在和无权访问均展示相同的不可用状态。
- 删除使用键盘可取消的原生确认对话框，确认后调用现有 DELETE API 并返回历史页面。
- 所有中文界面文本和标签名称来自 `zh-CN` locale 消息结构；浏览器不直接访问 Firestore。
- E2E 使用 Firebase Emulator 和完全虚构的数据，覆盖桌面 CRUD、未登录拦截和 360px 手机创建流程，Playwright 不启用失败重试。

## 4. 阶段 3：AI 反馈、安全检测和建议闭环

### 目标

在不影响记录可靠性的前提下，提供可审计的简短 AI 反馈，并完成建议效果反馈闭环。

### 工作范围

- Gemini 服务端 adapter 与测试 fake adapter
- 确定性风险规则、独立安全分类器和风险决策引擎
- 普通反馈结构化生成与后置校验
- 受控危机响应和普通失败降级
- `entryFeedback`、`suggestionOutcomes` 和最小化 `safetyEvents`
- 编辑后的分析过期与重新生成

### 验收标准

- Gemini 密钥只在服务端读取，客户端 bundle 和网络请求中不存在密钥。
- 保存记录在 AI 超时、拒绝或不可用时仍成功。
- 安全分类和普通生成是两个独立步骤；高风险时不调用或不展示普通建议。
- 高风险、否定句、历史叙述、中英文混写和 prompt injection 回归集通过既定阈值。
- 普通反馈最多一个建议，包含不确定性表达，不含诊断、药物、因果或依赖语言。
- 不合规或无效 AI 输出从不直接展示，改用审核过的降级文案。
- 每条结果保存来源类型、生成时间、模型、prompt 和安全策略版本。
- 用户可标记建议是否尝试及 1 到 5 的帮助程度。
- 普通日志和错误追踪中不出现完整日记或完整 AI prompt。

## 5. 阶段 4：30 天报告、测试权益和 Billing 接口

### 目标

完成第一版付费能力，但不接入真实支付。

### 工作范围

- `BillingProvider` 接口和 `TestBillingProvider`
- `featureFlags` 与 `entitlements`
- 30 天确定性统计聚合
- 报告结构化生成、安全校验和幂等任务
- 报告页面、数据不足状态和个人应对卡片

### 验收标准

- 关闭功能开关时，所有用户均不能从 API 生成报告。
- 无有效权益时，即使直接调用 API 也返回明确的无权限结果。
- 测试账户可通过受控 fixture 或管理脚本获得权益，不需要真实付款。
- 少于 14 个记录日时返回 `insufficient_data`，不生成强推断。
- 报告统计仅使用当前用户最近 30 个本地日期的数据。
- 相关性由服务端计算并标记样本数，文案明确相关性不等于因果。
- 报告包含规定章节，三个目标均为低风险，个人应对卡片不冒充危机计划。
- 相同周期重复请求幂等，不创建重复报告。
- Billing adapter 可被未来真实 provider 替换，报告 service 不依赖测试实现细节。

## 6. 阶段 5：导出、永久删除和隐私加固

### 目标

完成用户数据控制和可验证的账户生命周期。

### 工作范围

- JSON 原始数据导出和可选 CSV
- 近期认证
- 单条记录完整级联删除
- Cloud Tasks 驱动的幂等账户删除
- 日志脱敏、TTL、缓存头和最小权限审查
- 虚构 fixtures 与数据泄漏测试

### 验收标准

- 导出要求近期认证，并只包含当前用户账户、同意、日记、分析、结果和报告。
- 导出响应使用 `no-store`，服务器不留下公开临时文件。
- 删除账户后立即失去产品访问；可重试 worker 清理所有已知数据域和 Auth 用户。
- 删除任务中途失败后重试可完成，不产生恢复账户或孤儿数据。
- 新增集合必须通过“删除覆盖清单”测试，否则 CI 失败。
- 日志扫描测试不发现日记原文、token、Cookie、API key 或完整 AI prompt。
- 开发、测试、预发布和生产配置明确隔离。
- 隐私页和设置页准确说明导出、删除、AI 处理和已知备份限制。

## 7. 阶段 6：发布质量、可观测性和 Cloud Run 部署

### 目标

完成上线前的安全、质量、无障碍、性能和部署验证。

### 工作范围

- Cloud Run、Secret Manager、Cloud Tasks 和服务账号配置
- 预发布/生产环境隔离
- 结构化监控、告警和成本保护
- 全量 E2E、移动端、无障碍和错误恢复测试
- 安全与隐私上线检查
- 运维手册和回滚说明

### 验收标准

- 预发布环境可从干净仓库构建和部署，密钥不进入镜像或客户端。
- 健康检查、AI 超时、任务重试和错误降级可观测。
- API 错误率、AI 失败率、删除失败、任务积压和异常安全分支有告警。
- 关键用户路径在主流桌面和移动视口通过 E2E。
- 键盘操作、表单标签、焦点、对比度和错误提示通过基础无障碍检查。
- 跨用户访问、CSRF、会话固定、输入注入和速率限制检查通过。
- 生产使用独立 GCP/Firebase 项目和最小权限服务账号。
- 产品边界、危机资源、隐私文案和安全阈值已完成所需专业/法律审阅。
- 发布清单、回滚步骤、数据删除故障处理和模型回归流程有文档。

## 9. 预计 API

所有个人 API 使用 `/api/v1`，从会话取得 `uid`。

| 方法与路径                                  | 用途                                          |
| ------------------------------------------- | --------------------------------------------- |
| `POST /api/v1/auth/session`                 | 只验证 ID token 并换取会话 Cookie，不检查同意 |
| `DELETE /api/v1/auth/session`               | 登出并清除会话                                |
| `GET /api/v1/account`                       | 当前账户和偏好                                |
| `PATCH /api/v1/account`                     | 修改允许的偏好                                |
| `POST /api/v1/account/consents`             | 接受当前版本文案                              |
| `GET /api/v1/entries`                       | 分页读取历史                                  |
| `POST /api/v1/entries`                      | 创建记录（阶段 2A 不创建 AI 分析占位）        |
| `GET /api/v1/entries/[entryId]`             | 获取记录详情                                  |
| `PATCH /api/v1/entries/[entryId]`           | 编辑自己的记录                                |
| `DELETE /api/v1/entries/[entryId]`          | 删除记录及关联数据                            |
| `POST /api/v1/entries/[entryId]/feedback`   | 幂等生成或重新生成反馈                        |
| `PUT /api/v1/feedback/[feedbackId]/outcome` | 更新建议尝试结果                              |
| `GET /api/v1/trends?days=7`                 | 获取受控趋势聚合                              |
| `GET /api/v1/reports/30-day`                | 获取当前周期报告状态/内容                     |
| `POST /api/v1/reports/30-day`               | 检查权益并幂等生成报告                        |
| `GET /api/v1/account/export?format=json`    | 下载原始数据                                  |
| `POST /api/v1/account/deletion`             | 近期认证后请求永久删除                        |
| `POST /api/internal/tasks/delete-account`   | Cloud Tasks 调用的删除 worker                 |
| `POST /api/internal/tasks/generate-report`  | 可选的报告生成 worker                         |
| `GET /api/public/safety-resources`          | 获取公开地区安全资源                          |

内部任务端点必须校验 Cloud Tasks/OIDC 身份，不能只依赖不可见 URL。

## 12. 关键风险登记

| 风险                                      | 影响                                     | 当前缓解措施                                                | 上线门槛                     |
| ----------------------------------------- | ---------------------------------------- | ----------------------------------------------------------- | ---------------------------- |
| 高风险内容漏检或误检                      | 可能延误安全信息，或不必要地中断普通体验 | 规则扫描、独立分类器、保守决策、受控模板、回归语料          | 专业审阅阈值、文案和测试结果 |
| AI 输出诊断、药物或因果语言               | 对用户造成误导或伤害                     | 严格 prompt、结构 schema、后置策略校验、失败丢弃            | 安全回归集和人工抽样通过     |
| 用户对 AI 形成过度依赖                    | 偏离记录工具定位                         | 非聊天式短反馈、单一建议、边界常驻、禁止依赖语言            | UX 与文案审阅通过            |
| 日记正文进入日志或第三方工具              | 高敏感数据泄露                           | 默认不记录正文、日志字段白名单、泄漏扫描测试                | 预发布日志抽查无正文和密钥   |
| Admin SDK 绕过 Firestore Rules 后发生越权 | 跨用户数据暴露或修改                     | 固定用户路径、service 授权、deny-all 客户端规则、跨用户测试 | 全部授权测试通过             |
| Gemini 数据处理区域或条款不符合上线要求   | 无法在目标地区合规运营                   | 最小化输入、版本化同意、供应商评审、环境隔离                | 首发地区和供应商条款明确     |
| 危机资源过期或地区不匹配                  | 用户获得不可用信息                       | 地区化配置、核验日期、责任人和通用紧急服务提示              | 首发地区资源已核验           |
| 小样本相关性被误读为结论                  | 报告误导用户                             | 14 天门槛、样本数展示、确定性统计、非因果文案               | 报告统计与文案审阅通过       |
| AI 延迟、配额或成本失控                   | 记录流程变慢或服务不可用                 | 记录与 AI 解耦、超时降级、速率限制、用量监控                | 压测、预算告警和降级演练通过 |
| 删除任务部分失败或遗漏新集合              | 用户数据残留                             | 幂等 Cloud Task、固定删除清单、集合覆盖测试、失败告警       | 端到端删除和重试测试通过     |
| 时区和夏令时导致趋势错误                  | 日、7 天和 30 天统计不可信               | IANA 时区、保存时区快照、本地日期键、边界测试               | 日期测试矩阵通过             |
| 正式运营地区规则不明确                    | 隐私、成年确认和产品声明不适用           | 暂不锁定地区特定承诺，保留配置和版本化文案                  | 法律审阅和首发地区决策完成   |

## 13. 非阻塞决策与待确认项
