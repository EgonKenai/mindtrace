# MindTrace 隐私与数据保护设计

## 1. 原则

- 数据最小化：只收集提供记录、分析、导出、删除和安全信息所需的数据。
- 目的限制：不把日记用于广告、用户画像销售或未经同意的模型训练。
- 用户控制：用户可查看、修改、导出和删除自己的数据。
- 服务端隔离：个人数据访问经过认证、授权和资源所有权检查。
- 默认不记录正文：普通日志、监控和错误报告不包含完整日记或 AI prompt。
- 环境隔离：开发、测试、预发布和生产不共享用户、数据库或密钥。

本文件是工程设计，不替代针对正式运营地区的法律意见和公开隐私政策。

## 2. 数据清单与目的

| 数据类别   | 示例                             | 目的                                                | 是否必需           |
| ---------- | -------------------------------- | --------------------------------------------------- | ------------------ |
| 账户认证   | 邮箱、认证状态                   | 由 Firebase Authentication 用于注册、登录、找回账户 | 必需               |
| 应用账户   | locale、时区、地区、成年确认状态 | 产品准入、日期聚合、界面和安全资源                  | 部分必需           |
| 偏好       | 语言、时区、国家/地区            | 日期聚合、界面和安全资源                            | 时区必需，地区可选 |
| 同意       | 文案版本、接受时间               | 证明用户接受当前边界和处理说明                      | 必需               |
| 日记       | 数值、标签、自由文字             | 记录和个人趋势                                      | 必需               |
| AI 分析    | 反馈、建议、模型元数据           | 提供反馈和审计                                      | 使用 AI 时必需     |
| 建议结果   | 是否尝试、帮助评分               | 形成个人方法档案                                    | 可选               |
| 报告       | 聚合统计和报告内容               | 提供 30 天报告                                      | 使用报告时必需     |
| 安全元数据 | 风险级别、信号代码               | 执行和审查安全策略                                  | 最小化收集         |
| 运营元数据 | 请求 ID、错误代码、延迟          | 稳定性和安全监控                                    | 必需               |

不收集身份证、护照、精确地址、通讯录、麦克风、相册或后台位置。用户可能在自由文字中主动输入敏感信息，界面应提醒不要记录不必要的身份信息。

## 3. 数据流

1. 浏览器向 Firebase Authentication 提交登录凭据。
2. 浏览器将 Firebase ID token 发送给 MindTrace 服务端换取安全会话。
3. 日记通过同源 API 发送到 Cloud Run，并写入当前用户的 Firestore 路径。
4. 阶段 3B 只有在用户接受当前 AI 第三方处理说明后，服务端才可能把最小化输入发送给 Gemini。
5. 服务端先完成确定性安全路由，再使用官方 `@google/genai` 的无状态 `models.generateContent`；响应必须经过本地 strict schema 和内容安全校验，未经验证的输出不得保存或展示。
6. 浏览器只获得当前用户有权查看的数据。

AI 同意独立于日记基础功能。拒绝 AI 不影响日记、历史和趋势；普通反馈 API 在调用 Provider 前返回 `AI_CONSENT_REQUIRED`。同意页面说明第三方处理、发送的数据类别和用途，并说明 Provider 可能依据其条款为滥用监测保留提示词和输出。

阶段 3C 在记录详情页第一次按需生成前读取服务端同意状态。接受和拒绝均保存到版本化服务端记录；拒绝时浏览器不会调用反馈 API。生成结果只保留在当前页面内存中，刷新后消失，不写入浏览器存储。

## 4. 身份与访问控制

- API 从经过验证的服务端会话取得 `uid`，不接受客户端声明的所有者 ID。
- 每个 repository 查询都以该 `uid` 构造固定集合路径。
- 更新使用字段白名单，禁止客户端写入 owner、模型版本、生成时间或权益。
- 邮箱默认只保存在 Firebase Authentication 中，不复制到 `accounts/{uid}`。未来如确有业务需要，必须先完成隐私评审并补充同步、导出、删除和访问控制设计。
- Firestore 客户端规则默认拒绝所有业务数据读写。
- Cloud Run 服务账号仅获得所需 Firestore、Auth、Secret 和任务权限。
- 管理员和开发者默认不能通过产品界面浏览用户日记。
- 生产数据访问需单独的最小权限流程和审计，不使用共享账户。

## 5. 密钥与配置

- Gemini 密钥、任务签名密钥和服务端配置存储在 Secret Manager。
- Cloud Run 使用工作负载身份访问 Firebase/GCP，不提交服务账号 JSON。
- 本地秘密只进入被 Git 忽略的环境文件。
- 提供 `.env.example` 时只包含变量名和虚构占位值。
- 构建时公开变量只能包含 Firebase Web 公共配置和非敏感 UI 配置。
- 日志和错误对象必须对 `authorization`、Cookie、token、key 和 secret 字段脱敏。

## 6. 日志与分析

禁止：

- 日记正文、完整 AI 输入输出和数据导出内容
- 邮箱与正文拼接的错误消息
- 身份令牌、Cookie、API 密钥
- 将生产请求复制到开发工具或测试夹具

允许：

- 随机请求 ID、路由模板、状态码、延迟
- 用户 ID 的短期不可逆运维标识；若非必要则不记录
- schema 错误代码、模型版本、token 数和安全动作代码
- 删除任务状态和不含个人内容的错误代码

产品分析首版仅使用最小化事件，例如“记录创建成功”。不记录自由文字、数值内容或事件标签作为分析属性。

阶段 2 安全审查确认：

- 日记和趋势实现没有普通 `console` 或服务端日志调用；未知异常统一转换为不含原始消息的 `INTERNAL_ERROR`。
- schema 错误只返回允许的字段名和通用错误代码，不回显正文、标签值、所有者字段或完整请求体。
- 趋势查询不读取 `note` 或 `eventTags`，只读取五项数值与 `localDate`。
- E2E 和集成测试只使用 `example.test` 虚构账户、`mindtrace-demo` 虚构项目和明确标注的虚构记录。
- CI 中关闭 Playwright 截图与 trace；失败时只上传测试名称、状态和耗时的净化报告。

阶段 3A 隐私约束：

- Provider 输入只包含五项状态数值、受控标签、最多 1,200 个 Unicode 字符的清理后 note、locale 和非识别性契约字段。
- 不包含 uid、email、姓名、entryId、Cookie、token、IP、精确地址、精确时间戳、账户资料或 Firestore 路径。
- 安全路由在本地检查完整记录；危机、支持和降级响应不调用 Provider。
- 阶段 3A 不持久化反馈。未来 `analyses/{uid}/entryFeedback` 只能保存已验证最终结果和最小化元数据，并必须加入导出和账户删除覆盖。
- 反馈审计事件只包含 decision 和稳定 reason code；默认不记录日记、prompt、Provider 原始输出或原始错误。

阶段 3B 第三方处理约束：

- `@google/genai` 仅存在于 `server-only` 模块，API key 和 model 只从服务端环境读取。
- 使用无状态 `models.generateContent`；不使用 Interactions、chat、previous interaction ID、缓存、后台任务、工具或搜索。
- 缺少 key 或 model 时不发起请求，返回 `PROVIDER_NOT_CONFIGURED`。
- 只有 429、502、503 可重试一次；任何错误响应、SDK 消息和原始输出均不进入用户响应或普通日志。
- 自动化测试只使用注入 client/Fake Provider，不使用真实 key，不连接 Gemini。
- Gemini 对输入输出的保留、滥用监测、区域和训练用途以实际账户层级及届时有效的供应商条款为准；上线前必须再次核验并更新用户文案。

阶段 3C 界面约束：

- 浏览器只接收字段白名单内的最终 `FeedbackResult`，不接收 prompt、原始候选、SDK 错误或内部堆栈。
- reflection 和 suggestions 仅按纯文本展示，不执行 HTML。
- AI 同意弹窗和反馈区域不记录日记正文、标签、请求体或生成内容到控制台。
- 自动化浏览器测试使用虚构用户与拦截响应，不调用真实 Gemini。

## 7. 数据保留

初始保留策略：

- 账户、日记、分析和报告：保留至用户删除对应内容或账户。
- 安全事件元数据：建议短期保留并配置 TTL；具体期限在上线地区确认后决定。
- 完成的删除任务：短期保留状态后 TTL 删除，并尽快移除 `subjectUid`。
- Cloud Logging：使用短期、明确的保留期，不包含正文。
- 备份：若启用，必须记录保留周期、加密方式和删除账户后的最长到期时间。

在备份策略确定前，不得对外承诺“所有副本即时消失”。公开文案应准确说明活动系统删除和受限备份到期机制。

## 8. 数据导出

- 需要近期认证。
- 导出以机器可读 JSON 为主，包含 schema 版本、生成时间和各数据域。
- 可选 CSV 用于日记表格，不丢失 JSON 原始导出能力。
- 文件通过认证响应直接传输，设置 `Cache-Control: no-store`。
- 不把导出文件存入公开对象存储或发送到邮箱。
- 自动化测试验证导出只包含当前用户数据。
- 阶段 2A 新增的 `journals/{uid}/entries/{entryId}` 必须纳入未来 JSON 导出；本阶段不实现导出 API。

## 9. 单条删除与账户删除

### 单条删除

删除日记时，删除其 AI 反馈、建议结果和关联的最小安全元数据。报告若引用该记录，标记为过期并在下次查看时重新计算或提示重新生成。

### 账户删除

- 要求近期认证和明确二次确认。
- 请求后立即阻止继续使用并撤销会话。
- 后台幂等任务清理所有已知用户数据域，再删除 Firebase Auth 用户。
- 任务可重试并有失败监控。
- 完成后清除任务中的直接用户标识，任务文档按 TTL 删除。
- 不以“停用”代替删除。

删除范围至少包括：

- `accounts/{uid}` 及同意子集合
- `journals/{uid}` 及全部记录
- `analyses/{uid}` 及反馈和建议结果
- `reports/{uid}` 及报告
- `safetyEvents/{uid}` 及事件元数据
- `entitlements/{uid}`
- Firebase Authentication 用户
- 未来新增集合必须加入删除清单和自动化测试

阶段 2A 新增的 `journals/{uid}/entries/{entryId}` 已列入上述 `journals/{uid}` 删除范围；本阶段只实现单条日记删除，不实现账户删除 worker。

## 10. 开发与测试数据

- 只使用匿名、虚构人物和虚构日记。
- fixture 文本应明确标注为测试内容，不复制公开论坛或真实案例。
- 常规 CI 使用 AI fake adapter 和 SDK mock，不设置 `GEMINI_API_KEY`，不把测试日记发送到真实 Gemini。
- E2E 每个测试创建隔离用户并在结束时清理。
- Firebase Emulator 在每个 CI job 结束时销毁全部虚构测试数据；当前测试不连接真实 Firebase 项目。
- 禁止将生产数据库导出到本地排障。
- 截图、录屏和错误报告不得展示真实日记。

## 11. 第三方与供应商

上线前为 Firebase、Google Cloud 和 Gemini 建立供应商清单，确认：

- 数据处理条款和角色
- 数据存储和处理区域
- 模型输入是否用于供应商训练
- 默认和可配置保留期限
- 子处理者
- 安全事件通知机制
- 删除与导出支持

任何新分析、错误追踪或支付供应商都需要先完成数据流和最小化评审。

## 12. 用户界面要求

- 同意页使用易读中文分别说明产品边界、隐私和 AI 处理。
- 设置页提供时区、地区、数据导出和删除账户入口。
- 删除账户不使用误导性按钮或人为阻碍。
- AI 内容明确标识为 AI 生成或规则模板。
- 公开安全页面不要求 Cookie 同意或付费。
- 敏感页面默认避免被共享缓存，必要时使用 `no-store`。

## 13. 上线前隐私检查

- 数据地图与实际代码、集合和第三方调用一致
- Firestore 规则为默认拒绝并有 Emulator 测试
- API 跨用户访问测试全部通过
- 日志扫描未发现日记、token 或密钥
- 导出内容完整且只属于当前用户
- 删除任务覆盖全部集合并验证 Auth 删除
- Secret Manager 和服务账号权限最小化
- 隐私、同意、备份和保留文案经过法律审阅

## 14. 阶段 4A 长期摘要与行动计划隐私说明

阶段 4A 的长期摘要为确定性按需计算，不调用真实 Gemini，不发送第三方 AI Provider，不保存完整 prompt 或 Gemini 原始输出。摘要查询只读取当前用户 `journals/{uid}/entries` 中的 `localDate`、五项数值和受控标签，不读取或复制完整日记正文。

摘要窗口使用当前账户 IANA 时区生成最近 7/14/30 个本地日期，但记录归属仍以保存时的 `localDate` 为准。缺失日期保留为空，不伪造为 0。窗口内无记录时返回 `insufficient_data`。

行动计划只保存用户明确创建或更新的手动计划和行动项，路径为 `plans/{uid}/items/{planId}` 和 `plans/{uid}/items/{planId}/actions/{actionId}`。阶段 4A 不让 AI 自动创建计划；未来如增加 AI 建议计划，必须经过用户确认后才保存，并更新本隐私说明。

未来 JSON 导出和账户删除必须覆盖 `plans/{uid}` 及全部行动项。长期摘要当前不持久化；如果未来新增 `longTermSummaries/{uid}`，也必须加入导出、删除 worker 和自动化覆盖测试。本阶段不实现导出或账户删除。
